01 — Hosts

Your whole fleet, one keystroke away

Compact host lists, groups and reusable commands. Type an ssh command into the search field to connect at once.

  • Groups and sorting shared by every client
  • Quick connect from the search field
  • Jump hosts, saved or temporary for one tab

02 — Terminal

A terminal that reads the log with you

Errors, warnings, successes, IP addresses and links are colored in plain output, even when the remote program prints no color at all.

  • Keyword groups, colors and word lists are editable
  • Up to 5,000,000 lines of scrollback
  • SSH and Telnet; local shell and serial console on desktop

03 — Files

Files without leaving the session

SFTP and SCP file workspaces sit next to your terminals. Copy between two hosts directly over SSH, or relay through your device.

  • Copy and move between hosts
  • Open remote files in system apps on Windows and macOS
  • Upload prompt after a local save

04 — Layout

Split it the way you think

Put terminals and file views side by side in panes, then save the arrangement as a window set to bring it back later.

  • Split panes in every client
  • Saved window sets
  • Separate OS windows on desktop

Security model

The server syncs ciphertext

Hosts, keys and passwords are encrypted on the device before they are synced. The sync server stores ciphertext records and checks signed device identities.

Your device

host db-primaryuser deploykey ed25519 ••••port 22
ciphertext

Your server

host db-primaryuser deploykey ed25519 ••••port 22
ciphertext

Your other devices

host db-primaryuser deploykey ed25519 ••••port 22
01

Local profiles

Native clients can keep an encrypted profile on the device and never talk to a server.

02

Private by default

Each account is either private (zero knowledge) or explicitly admin-visible, with a notice to the user and a recorded view log.

03

Encrypted at rest

The server database is SQLCipher-encrypted, snapshots included, with the key kept outside the data volume.

04

Scrollback stays yours

Scrollback spilled to disk is sealed with XChaCha20-Poly1305 under a key that only exists in memory.

Self-hosted

Your sync server, on your hardware

The server is a single Rust service with Docker Compose files. It runs the encrypted sync API, organizations and the temporary access gateway.

Docker with Compose 2.24 or later.

Server guide↗
bash
$ git clone https://github.com/aterm-project/atermius.git && cd atermius$ cp deploy/.env.example deploy/.env$ docker compose --env-file deploy/.env -f deploy/compose.yaml \ run --build --rm --no-deps server \ database-key-generate --out /keys/database.key$ docker compose --env-file deploy/.env -f deploy/compose.yaml \ -f deploy/compose.web.yaml up -d --build
